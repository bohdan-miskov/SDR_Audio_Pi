# Архітектура збору даних та донавчання моделі (MLOps Pipeline)

Цей документ описує життєвий цикл моделі машинного навчання в нашій підсистемі аудіодетекції. 
Система використовує концепцію "Data Flywheel" (Active Learning) для поступового покращення точності розпізнавання FPV-дронів у реальних бойових умовах, уникаючи при цьому проблеми катастрофічного забування.

## Чому Raspberry Pi не вчиться автономно?
Тренування (Backpropagation) безпосередньо на мікрокомп'ютері відключено з наступних причин:
1. **Запобігання Data Poisoning:** Мережа не повинна автоматично запам'ятовувати хибні звуки (наприклад, трактори чи бензопили) без верифікації людиною.
2. **Апаратні ліміти:** Процес тренування перевантажить процесор Raspberry Pi, що призведе до пропуску реальних загроз в ефірі.

## Життєвий цикл моделі (Continual Learning Cycle)

Процес розділено на два фізичні середовища: **Edge (Raspberry Pi)** та **Local/Server (Комп'ютер інженера)**.

### Етап 1: Розвідка та Логування (Edge)
* Модуль сканування `live_scanner_audio.py` працює в штатному режимі, використовуючи актуальний файл `conv.keras`.
* Якщо нейромережа фіксує звук із рівнем впевненості **від 40% до 80%** (аномалія/невідомий дрон/схожий шум), активується модуль **Smart Audio Logger**.
* Система автоматично експортує 5 секунд цього аудіоефіру у форматі `.wav` у директорію `/logs/anomalies/` для подальшого аналізу.

### Етап 2: Збір "врожаю"
* Інженер періодично підключається до вимірювального стенду і завантажує накопичені аудіофайли з папки `/logs/anomalies/` на свій комп'ютер.

### Етап 3: Розмітка даних (Data Annotation)
* Інженер відслуховує зібрані семпли.
* Файли сортуються вручну у відповідні директорії локального датасету:
  * Нові звуки пропелерів $\rightarrow$ `dataset/Clean_Audio/drone/`
  * Хибні спрацьовування (вітер, техніка) $\rightarrow$ `dataset/Clean_Audio/noise/`

### Етап 4: Перенавчання (Local/Server)
* На комп'ютері інженера запускається скрипт `python -m src.ml.train`.
* Скрипт автоматично сканує оновлену папку `dataset/`, витягує MFCC-спектрограми та тренує модель на розширеній базі.
* Генерується новий, більш точний файл ваг `models/conv.keras`.

### Етап 5: Деплоймент (OTA Update)
* Новий файл `conv.keras` завантажується на Raspberry Pi, замінюючи стару версію.
* Система продовжує сканування з підвищеною точністю, вміючи розрізняти нові типи загроз та ігнорувати нові типи шумів.
